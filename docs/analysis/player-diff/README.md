# Game-Maker player machine code: inventory and function matches

What each Game-Maker player build changed, measured on the machine code. Everything here is
generated by [`scripts/player-diff/gmpdiff.py`](../../../scripts/player-diff/README.md) except
this page; rerun it rather than editing the files.

| file                                             | what                                                                                                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| [`inventory.md`](inventory.md) (`inventory.tsv`) | every player build held: canonical copy, SHA-256, sizes, MZ header, linker mark, packer, predecessor, the comparison pairs and what is missing |
| [`copies.tsv`](copies.tsv)                       | every copy found (430), and how it relates to its build's canonical copy                                                                       |
| [`pairs.md`](pairs.md)                           | function counts for every pair                                                                                                                 |
| `pairs/<old>__<new>/summary.md`                  | one pair: changed, added and removed functions; header, layout, DOS services, I/O ports, embedded files, data and strings                      |
| `pairs/<old>__<new>/functions.tsv`               | one pair's full match table                                                                                                                    |

The three pairs the question is about:

- [1.00-xfer → 1.04](pairs/1.00-xfer__1.04/summary.md): what 1.04 changed (no 1.01–1.03 held).
- [2.00 → 2.02](pairs/2.00__2.02/summary.md): what 2.02 changed (no 2.01 held).
- [2.04 → 3.00-xfer](pairs/2.04__3.00-xfer/summary.md): what 3.0 changed (2.04 is the newest
  earlier player held; [2.02 → 3.00-xfer](pairs/2.02__3.00-xfer/summary.md) is a control).
  Read with [the 3.0 analysis](../player-diff-3.0.md), which attributes every function and
  byte to a module and says what each change is.

The other pairs complete the chain (1.04 → 2.00, 2.02 → 2.04) or are controls (the 1.00 and
3.00 PLAYGAME builds, a second 3.00 build).

## Reading the numbers

A function's status compares machine code only: _identical_ (same bytes, relocations masked),
_relocated_ (same code, things moved), _calls-differ_, _data-moved_ (only data offsets moved),
_constants_ (same instruction shape, other numbers or strings) and _changed_. Matches have a
confidence; low ones are leads, not findings. The scripts' README gives the method and its
limits. Reports carry no owner stamps, and addresses and phone numbers found in the binaries
are redacted.

Not committed: historical binaries from the optional local archive corpus, their full
disassembly and per-function diffs. Some binaries carry owner stamps; these remain private
in the tool's work folder.

Read the [consolidated report](../player-machine-code-diff.md),
[1.04 analysis](../player-diff-1.04.md), [2.02 analysis](../player-diff-2.02.md),
and [3.0 analysis](../player-diff-3.0.md) for interpretation and caveats.
