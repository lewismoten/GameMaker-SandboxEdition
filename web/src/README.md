# web/src: a map

Game-Maker: Sandbox Edition in the browser. Two pages load this code:

- `index.html` → [`main.ts`](main.ts): the site. It opens on the **1994 desk** (`desk/`, a
  simulated DOS PC running the ported designers; no DOS or x86 code runs) or **today's web** interface
  (`editor/`), whichever the visitor used last (`localStorage` `gm-ui`).
  [`urlState.ts`](urlState.ts) keeps the place in the hash (`#/`, `#/game/cd:nebula`,
  `#/p/<project>/<file>?scene=3`, `#/help/<section>`, `#/cast`, `#/credits`, `#/achievements`, `#/mac`, `#/windows`,
  `#/linux`, `#/desk`), so a reload or a shared
  link comes back to it; [`seo/route.ts`](seo/route.ts) keeps the page's title and share
  tags in step with what is on screen. `?open=<url>` and `?receive` open a game sent by another site
  ([`linkIn/`](linkIn), [`docs/embed.md`](../../docs/embed.md)).
- `dos.html` → [`dosPage/dosPage.ts`](dosPage/dosPage.ts): DOS Game-Maker, the desk's PC on
  its own (`?game=<id>` opens that game in Game-Maker, `?run=dos` or `?run=bbs`; `?project=<id>&run=play|design` a game kept in this browser). It loads no
  desk code (`dosPage/boundary.test.ts`); `#/dos` and `#/dos/<id>` on the site lead to it.
  [`viewSwitch.ts`](viewSwitch.ts) is the Desk | DOS | Web switch in all three headers.
- `play.html` → [`play.ts`](play.ts): a full-window player for one game
  (`?game=<id>`, `?project=<id>`, or the game bundled in an exported web app). Each
  bundled game also has its own copy of the page, `play-<id>.html` (made at build time,
  naming its game with `<meta name="gm:game">`), so link previews show that game.

Every module starts with a comment saying what it is for. Code ported from the original C
source names the file it came from (`code/GM/*.C` in the repository root).
[`keepTogether.ts`](keepTogether.ts) is the one phrase no word wrap splits, THE CHEZ: the
canvases' and BBS screens' wrappers split their text with its `words()`; HTML text uses a
no-break space.

## Main flows

**Desk or modern UI.** `main.ts` is a tiny entry: it loads `desk/desk.ts` or
`modernUi.ts` (today's home and workspace; the Guide is its own download) only for the interface being shown, and the
editors (`editor/editors/registry.ts` `loadEditor`) one at a time, as files of each kind are opened, so each interface is its own
download. `offline.ts` registers the service worker (`siteWorker.ts`), which precaches only
the app shell and caches games as they are used; a new deploy waits for the visitor to say
"Reload". A hosted game comes in one request: its pack (`<id>.<hash>.gmpak`, all its files
gzipped in play order, `project/gamePack.ts`), read as it arrives so play starts once the
.gam is in (`loadHostedGame`, `streamHostedGame`). Single files go through `fetchGameFile`
(`project/files.ts`), which shares each request and reads from a pack already at hand. The
build also puts in the catalog what pages would otherwise fetch files to work out (the
quick health check, a box's captions). Lists load `games/catalog.json` (`loadCatalogList`), and a game's notice, manual and
printables come from `games/details/<id>.json` when it is opened (`withDetails`); pictures of
listed games are prebuilt in `games/shots/` (`gfx/levelPicture.ts`; the tiles' title screens, `gfx/titlePicture.ts`). `main.ts` starts one or
the other and switches between them;
the desk's PC can also open today's editors full screen on its monitor
(`retro/computer.ts` `openEditor`, through the same editor registry).

**Formats → engine → player.** A game is a `GameFiles` (`project/files.ts`): loaded from
the CD catalog, IndexedDB, a zip or a folder. A hosted game on the play page streams in
(`project/streamGame.ts`): it starts once its `.gam` is in, and the engine asks for each
file just before reading it (`engine/machine.ts` `need`). `player/player.ts` mounts a canvas and runs
`engine/game.ts`, which parses the `.gam` and the files each scene names with
`formats/`, and plays them on the `engine/machine.ts` screen, keyboard and timers (an
18.2 Hz game clock, 145.6 Hz for scrolling and sound) with `audio/` for music and
sound.

**Editors.** Each `editor/editors/<kind>/<kind>.ts` calls
`registerEditor([...kinds], fn)` (`editors/registry.ts`). The workspace
(`shell/workspace.ts`) lists the project's files by kind and renders `editors[kind]` for
the one chosen; edits go through `core/project.ts`, which autosaves to IndexedDB. Files
are always written in the original binary formats.
The block set editor (`editors/blocks/`) and the character editor share block groups
(`blockGroups.ts`: a picture drawn across several blocks, kept in the companion file), the
group shown assembled (`groupView.ts`), and live animation previews at the game's tick rate
(`animClip.ts` builds them from block chains, monsters and character sequences;
`animPlayer.ts` plays them).
The character editor makes a sequence's mirror (`editors/character/characterMirror.ts`, pure:
both blocks of each frame mirrored and each move's x negated, on the same blocks turned or on
new mirrored blocks; `characterMirrorPanel.ts`, its bar) and keeps the links between a
sequence and its twin, and a block and its mirror, in the companion file.
The music editor's Accompany… and Copy tune… (`editors/music/accompanyDialog.ts`,
`copyTuneDialog.ts`) use `editors/music/arrange/`, pure: `harmony.ts` hears a tune's key and
chords, `styles.ts` holds the band's patterns and preset sounds, `accompany.ts` writes bass,
chords and drums in rhythm mode around the tune, and `copyTune.ts` copies a tune at a new speed
and pitch. The demo recordings editor's Let the bot play… (`editors/recording/botDemoDialog.ts`)
runs `botDemoWorker.ts` (through `botDemoClient.ts`): the walkthrough bot plays to the chosen
scene, and `botDemo.ts` plays its walkthrough on the engine and writes the keys down at the demo
recorder's ticks as a `.REC`.
The animation editor's Scene maker (`editors/animation/scene/`) draws an `.FLI` from a scene kept
in the companion file: `sceneModel.ts` (backgrounds and tracks of timed items), `sceneText.ts` (the
8x8 font, text motions, and the warnings and fit that keep text inside 320x200), `sceneAssets.ts`
(the game's pictures, maps and sprites, sprite colors matched into each background's palette),
`sceneRender.ts` (frames, fades and the `.FLI`) and `sceneGenerate.ts` (Intro, Cast and Story
made from the game's files; a monster's name for its Cast card is the one the monster editor
keeps in the companion, `editors/monsters/monsterNames.ts`); `sceneEditor.ts`, `sceneTimeline.ts` and `sceneInspector.ts` are its
picture, timeline and settings, and `sceneMaker.ts` offers it when a new animation is made.

A new game's opening (`tools/opening/`): "+ Make a new game" and the start scene's 🎬 Opening sting…
(`openingDialog.ts`) offer the "Made with Game-Maker: Sandbox Edition" card as an animation, a
still picture or none, and a "<name> PRESENTS" card (`openingFields.ts`). The card is made once by
`games/kit/madewith.ts` into `public/opening/`; `openingCards.ts` fetches it and draws the presents
card with the Scene maker's renderer, and `openingWire.ts` puts them first in the title `.LST` as
the game's own files (what was added is kept in the companion, so it comes out again exactly). The
Sandbox, CD and imported games never get one.

The palette editor's Color vision tab (`editors/palette/visionPanel.ts`) shows a level as seen in
grayscale and with color-vision differences (`colorVision.ts`) and lists colors that look alike
there (`visionWarnings.ts`); `visionDismissed.ts` keeps the ones a designer dismissed as meant to
look alike, in the companion file on the `.pal`.

**Exports.** A game's one Download button opens the chooser in `editor/shell/download.ts`,
which calls `export/`: `exportWebApp.ts` (the built player listed in `player-files.json`,
the game's files, a manifest and a service worker), `exportSinglePage.ts` (`standalone.html`
with the game embedded, built by `../scripts/singlePageBuild.ts`), `exportWebPlayer.ts` (the web player, `web-player.html`, with the
game's folder and a `games.json`), `exportDos.ts` (the files
plus the CD's `XFERPLAY.EXE`, renamed after the game), and the Mac, Windows and Linux
downloads (`macApp.ts`, `winApp.ts`, `linuxApp.ts`), which put the single page into the
players in `../public/mac`, `win` and `linux`, with `THIRD-PARTY-NOTICES.txt` (`notices.ts`).
`export/downloadable.ts` says which catalog games may be downloaded, for the button and for
`../scripts/macDmg.ts`, `winExe.ts` and `linuxTar.ts`, which run the same code from the
command line.

**Media.** `media/demo.ts` plays a `.REC` demo in the player; `media/demoPreview.ts` plays one inside a picture on the home page, with the demos' sound choice (`demoAudio.ts`). `walkthrough/` plays a Sandbox game's `walkthrough.json` and renders it to MP4 (`exportVideo.ts`, `mp4av.ts`). `media/video.ts` turns
canvases into video: frame by frame with WebCodecs and `mp4Mux.ts`, or live with
MediaRecorder (with the game's sound from `audioTap.ts`). `gifEncode.ts` writes animated
GIFs and `wav.ts` sounds. The desk's capture card (`desk/pc/capture.ts`) takes screenshots
and recordings of the PC's screen with `screenCapture.ts` and the live recorder.

## Build-time code

[`../scripts`](../scripts) holds Vite plugins: `cdGames.ts` serves the CD's games and
`../games` (and writes them into the build, with the catalogs and gzip copies),
`gameShots.ts` draws each listed game's pictures into `games/shots/`, `singlePageBuild.ts` builds
`standalone.html`, `hostedPlayerBuild.ts` the web player (`web-player.html`, `player/index.html` and `player/games.json`), `seoBuild.ts` puts tags, JSON-LD and readable text into the pages and
writes (and serves in dev) `robots.txt`, `sitemap.xml`, `llms.txt`, each game's
`play-<id>.html` and its preview picture `og/<id>.png` (drawn by `ogImage.ts`). `credits.ts` writes the Credits page's `deps.json` and `levelSecrets.ts` the Level Maps' `levelSecrets.json` (both run by hand; their tests fail until they are rerun). `../vite.config.ts` also emits the
service worker and `player-files.json`. `bbsGifs.ts` is not a plugin: run once by hand, it
made the BBS gallery's pictures in `../public/bbs`; neither are `castArt.ts` and
`castSprites.ts` (the Cast page's pictures in `../public/cast`, from the other `cast*.ts` drawings) or the download scripts above.
