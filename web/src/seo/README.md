# `seo/`: what search engines and link previews learn

Part of the [source map](../README.md). Page titles, descriptions, Open Graph and Twitter tags and
schema.org JSON-LD for the site and its game pages.

Entry points: `web/index.html` loads `route.ts` as its own module script alongside `main.ts`.
The build's `web/scripts/seoBuild.ts` uses `site.ts` and `siteSections.ts`;
`web/scripts/seoStaticPages.ts` and the neighboring `export/` area use `site.ts`.

- `site.ts`: pure functions for the public address, descriptions, meta tags and JSON-LD. Shared by the build, the pages and the web exports.
- `route.ts`: watches hash changes, the document title and `#app`'s class. It keeps description and share-title tags in step with the route, preserving specific titles such as a game's name. Editor routes get `noindex`; other routes get `index, follow`. This does not make each hash route a separately indexed page.
- `siteSections.ts`: the home page's crawlable map of the `#/…` pages, plus WebSite and magazine (Periodical) JSON-LD.
- `magazineText.json`: TURBO BUTTON's words as plain text for the static `magazine.html`. Generated by `scripts/magazineText.ts`; never edit by hand.

Must not: name or hint at a secret game in any tag, description or list (`AGENTS.md` content rules).
Keep `site.ts` free of the DOM so the build can run it in Node. Its game metadata helpers
accept caller-supplied data; they are not a secret-game filter. Callers must select public content.

Tests: `seoPages.test.ts`, `siteSections.test.ts`, `scoopFeed.test.ts`. The magazine data is kept in
step by `manual/magazine/magazineText.test.ts`.

Check: `cd web && npx vitest run src/seo`.
