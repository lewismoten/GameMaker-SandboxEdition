# AGENTS.md

Notes for AI coding agents working in this repository. The README covers the project for
people. This file covers how to work in it without breaking things.

## What this is

**Game-Maker: Sandbox Edition** is a fork of RSD Game-Maker 3.0 (1991–1995). It has:

- a web port of the DOS engine (PLAYGAME)
- an in-browser editor
- a 1994 "desk" PC with DOS, Game-Maker, BBSes and tools
- a set of new games built in code (`games/`)

The original DOS source is in `code/` and the CD in `cd/`. The rest is new.

## Layout

| Path | What it holds |
| --- | --- |
| `web/` | The Vite + TypeScript app: engine (`src/engine`), editor (`src/editor`), desk (`src/desk`, `src/retro`), exports (`src/export`), manuals and printables (`src/manual`). `web/src/README.md` maps it. |
| `games/<id>/` | One game each, generated by `build.ts` into `disk/` (the real DOS files). It also has `src/`, `tools/` (bot, route, check, walkthrough), `about.json`, `manual.json` and `printables.json`. |
| `games/kit/` | Shared builders and checks for the games. See `games/kit/README.md` and `games/kit/TIN-HEARTS.md`. |
| `mac/`, `win/`, `linux/` | Native player shells for the downloads. |
| `code/` | Original C/C++ source. It is the reference for engine behavior. |

## Commands (run from `web/`)

```sh
npm install
npx tsc --noEmit -p .                              # typecheck
npx vitest run                                     # tests
npx vite-node ../games/<id>/build.ts               # rebuild a game's disk/
npx vite-node ../games/<id>/tools/check.ts         # bot plays it; must win without losing a life
npx vite-node ../games/<id>/tools/walkthrough.ts   # re-record its walkthrough (uses { clips: true })
npx vite-node ../games/kit/clipCheck.ts <id>       # no voice clip cut off at a level start or end
npx vite-node ../games/kit/textfitCheck.ts <id>    # text fits its DOS screens
npx vite-node ../games/kit/hiddenView.ts <id>      # tin hearts and eggs are out of sight
npx vite-node ../games/kit/tinHearts.ts check      # every heart is found when touched
npx vite-node ../games/kit/playtime.ts             # the only writer of box play hours
```

After changing a game, rebuild it and run its checks. Commit the source and the rebuilt
`disk/` together. A refactor must not change any `disk/`, `walkthrough.json` or demo bytes.

## Working rules

- **Commits:** commit small and often: one game or one feature per commit, with no more
  than about 3 uncommitted files at a time. Use `git commit -- <paths>` so you only commit
  your own files. Never push, and never rewrite history.
- **Dev server:** the maintainer keeps a dev server open on port 5317. Never restart or stop
  it, and never make that page reload. Verify with your own headless browser (playwright-core,
  channel `chrome`) against it. For production checks, use a scratch build
  (`vite build --outDir <tmp>`) previewed on another port, and stop it afterwards. Edits to
  `web/index.html` and `web/vite.config.ts` should be rare and deliberate.
- **Formatting:** don't run `prettier --write` on existing files. There's no config, and it
  restyles whole files. Match the surrounding style instead.
- **Files:** keep them small, one purpose each, with a short header comment.
- **DOS fidelity:**
  - The engine matches PLAYGAME, so check `code/GM` before changing engine behavior.
  - Editor features must not change how games save or export to DOS.
  - Editor-only data goes in the project's companion file (`web/src/project/companion.ts`),
    which DOS, native and web-page exports never include.
- **Accessibility and layout:** keyboard reachable, labelled, 24px targets, and no
  horizontal scroll at 390px. Editor and home views should fit one screen. Check new UI with
  axe at 1440 and 390, in light and dark.
- **Permissions:** if a command is blocked, stop and report it. Don't work around it.

## Content rules for anything that ships (games, text, art, pages, commit messages)

- **Secret games:**
  - A game whose `about.json` has `"secret": true` must never be named, counted, linked or
    hinted at outside its own folder. That includes commit messages and screenshots.
  - Test browsers should start with no felt eggs found, so its box never shows.
- **Privacy:**
  - No real addresses or license plates. The car's plate THE CHEZ is fine.
  - Fictional addresses must be obviously fake, e.g. "P.O. Box 000".
  - Phone numbers are 555-01xx. Two stay on purpose: 1-412-555-SAND and Jenny's 867-5309, the song's number everyone tries.
  - No membership or lineage organizations.
  - No health, grief or money material. The one exception is the lactose-intolerance game.
- **Clowns are always friendly.** Never scary, villains or jump scares. The maintainer, Doc Leo,
  is in a clown club that entertains children.
- **Trademarks:** use generic words instead of casual trademarks ("building blocks", not a
  brand). Lyrics quoted word for word and historical tech names (Sound Blaster, MS-DOS,
  VGA…) stay; NOTICE.md lists them.
- **Spelling:**
  - **Gwinn** (two n's) is the troublemaker dog.
  - **Teddy** is the corgi; one ear is drawn shorter on purpose.
  - **Doc Leo** is never "Dr. Leo".
  - **THE CHEZ** is a tomato-red 1976½ CitiCar with a black roof and only the door window
    from the side. It has two charcoal stripes with red between them and a white pinstripe,
    stepping up in an S behind the door; white wheels; square bumpers; and the charge port
    at the rear passenger side. Draw it with `games/kit/chez.ts`.
- **Bard of Bizarre credits:** music and vocals made with Riffusion (now Google Flow
  Music); lyrics shaped by ChatGPT from the maintainer's prompts. Exceptions are noted in
  NOTICE.md.
- **Originality:**
  - Write manuals and text fresh. Don't copy RSD's printed manual.
  - The maintainer's reference photos are reference only, unless they're asked for.
- **Voice clips:** a level's ending voice must play to the end (the next scene's intro cuts
  it). Bots wait for clips (`sim.waitForClip()`). Score and pickup sounds must not cut voices.

## Before you finish

Run tsc and vitest. Run the game checks above for any game you touched. Then report what
changed, the commits, how you verified it, and anything left undone.
