# AGENTS.md

Notes for AI coding agents working in this repository. The README covers the project for
people. This file covers how to work in it without breaking things.

## What this is

**Game-Maker: Sandbox Edition** is a fork of RSD Game-Maker 3.0 (1991–1995). It has:

- a web port of the DOS engine (PLAYGAME)
- an in-browser editor
- a 1994 "desk" PC with DOS, Game-Maker, BBSes and tools
- a set of new games built in code (`games/`)

The original DOS source is in `code/` and the CD in `cd/`. The rest is new.

## Layout

| Path | What it holds |
| --- | --- |
| `web/` | The Vite + TypeScript app: engine (`src/engine`), editor (`src/editor`), desk (`src/desk`, `src/retro`), exports (`src/export`), manuals and printables (`src/manual`). `web/src/README.md` maps it. |
| `web/src/editor/check/` | The editor's Level check and walkthrough bot, with no DOM (they run in Web Workers). Its panel is `editors/map/check/`; its badges, Before You Upload list and Make a walkthrough are in `editor/widgets/`. |
| `web/src/linkIn/` | Opening a game another site links to or sends by postMessage. Its protocol and limits are in `protocol.ts`; `docs/embed.md` is the site owners' side. |
| `docs/` | `embed.md` (opening games from other sites, with `examples/`), `web-player.md` (the web player), `editor.md` (a tour of the web editor, with its screenshots in `screenshots/editor/`), `history.md`, and the README's screenshots. |
| `games/<id>/` | One game each, generated by `build.ts` into `disk/` (the real DOS files). It also has `src/`, `tools/` (bot, route, check, walkthrough), `about.json`, `manual.json` and `printables.json`. |
| `games/kit/` | Shared builders and checks for the games. See `games/kit/README.md` and `games/kit/TIN-HEARTS.md`. |
| `mac/`, `win/`, `linux/` | Native player shells for the downloads. |
| `code/` | Original C/C++ source. It is the reference for engine behavior. |

## Commands (run from `web/`)

```sh
npm install
npm run format                                     # Prettier: web/, games/*.ts, code/README.md
npm run format:check                               # what CI runs
npm run lint                                       # ESLint (type-aware) on web/; lint:fix fixes
npx tsc --noEmit -p .                              # typecheck
npx vitest run                                     # tests
npx vite-node ../games/<id>/build.ts               # rebuild a game's disk/
npx vite-node ../games/<id>/tools/check.ts         # bot plays it; must win without losing a life
npx vite-node ../games/<id>/tools/walkthrough.ts   # re-record its walkthrough (uses { clips: true })
npx vite-node ../games/kit/clipCheck.ts <id>       # no voice clip cut off at a level start or end
npx vite-node ../games/kit/textfitCheck.ts <id>    # text fits its DOS screens
npx vite-node ../games/kit/hiddenView.ts <id>      # tin hearts and eggs are out of sight
npx vite-node ../games/kit/levelCheck.ts <id>      # the editor's Level check finds nothing new
npx vite-node ../games/kit/tinHearts.ts check      # every heart is found when touched
npx vite-node ../games/kit/playtime.ts             # the only writer of box play hours
npx vite-node ../games/kit/versionCheck.ts         # a game changed since the last push to master has a higher version
npm run check:games                                # all of the game checks above, every game, a table
npm run check:games -- --game <id> --quick         # one game, without the rebuild compare
npm run dosbox                                     # dosbox/ (git-ignored) to mount as C: in DOSBox
```

After changing a game, rebuild it and run its checks (`npm run check:games -- --game <id>` runs
them all and also confirms the committed `disk/` matches a fresh build). Commit the source and the rebuilt
`disk/` together. A refactor must not change any `disk/`, `walkthrough.json` or demo bytes.
If a game's `disk/` has changed since the last push to master, bump its `"version"` in `about.json` once
(the game's text reads it from there): major (1.1 → 2.0) for new, removed or reordered levels or a big
gameplay change, minor (1.0 → 1.1) otherwise. `versionCheck.ts` (part of `check:games`) reports a game that needs one.

## The original repository's files

`code/`, `cd/` and `runtime/` came from the original 2014 source release. They are kept to
preserve what was there.

- Don't edit, move, rename, reformat or delete anything in them unless the maintainer
  directly asks you to.
- Don't lint, format or "fix" them. The one exception is `code/README.md`, a doc this fork
  added, which Prettier formats. The root `.prettierignore` leaves everything else in these
  folders out.
- Read them freely.
- A few files were removed on purpose: third-party libraries and binaries not covered by the
  MIT License. Each removal is documented in its commit and in NOTICE.md, so don't restore them.

## Working rules

- **Commits:** commit small and often: one game or one feature per commit, with no more
  than about 3 uncommitted files at a time. Use `git commit -- <paths>` so you only commit
  your own files. Never push, and never rewrite history.
- **Dev server:** the maintainer keeps a dev server open on port 5173. Never restart or stop
  it, and never make that page reload. Verify with your own headless browser (playwright-core,
  channel `chrome`) against it. For production checks, use a scratch build
  (`vite build --outDir <tmp>`) previewed on another port, and stop it afterwards. Edits to
  `web/index.html` and `web/vite.config.ts` should be rare and deliberate.
- **Formatting and lint:** run `npm run format` and `npm run lint` (from `web/`) before
  committing. The configs are the style source of truth: `.prettierrc.json` and
  `.prettierignore` at the root, and `web/eslint.config.js`. Writing
  `web/vite.config.ts` or a file it imports restarts the dev server and reloads every open
  page, so change those only when the maintainer has it stopped.
- **Formatting-only commits:** a commit that only reformats goes in `.git-blame-ignore-revs`
  (its full hash, with a comment line). For local `git blame` to honor it, run
  `git config blame.ignoreRevsFile .git-blame-ignore-revs` once in the clone.
- **Files:** keep them small, one purpose each, with a short header comment. Export only
  what another file imports.
- **Loading:** each editor, the desk, today's web and the Guide are separate chunks loaded
  when first used (`editor/editors/registry.ts` `loadEditor`, `main.ts`). Import their
  modules dynamically from elsewhere, not statically. `dos.html` must load nothing under
  `src/desk` (`dosPage/boundary.test.ts`).
- **Docs:** when you add an area, a module with a new job, or a command, add it to the area's
  README (indexed from `web/src/README.md`; `web/scripts/README.md` for build-time code,
  `games/kit/README.md` for the kit) in the same commit. A new area gets its own README and a
  line in the index.
- **Agent notes stay out of the repo:** progress files, briefs and probes for a run of agents
  (such as an overnight plan's per-wave progress files) go in the agent's scratchpad, not
  here. Notes for the maintainer go in `.for-lewis/`, which git ignores.
- **DOS fidelity:**
  - The engine matches PLAYGAME, so check `code/GM` before changing engine behavior.
  - Editor features must not change how games save or export to DOS.
  - Editor-only data goes in the project's companion file (`web/src/project/companion.ts`),
    which DOS, native and web-page exports never include.
- **Accessibility and layout:** keyboard reachable, labeled, 24px targets, and no
  horizontal scroll at 390px. Editor and home views should fit one screen. Check new UI with
  axe at 1440 and 390, in light and dark.
- **Permissions:** if a command is blocked, stop and report it. Don't work around it.

## Content rules for anything that ships (games, text, art, pages, commit messages)

- **Secret games:**
  - A game whose `about.json` has `"secret": true` must never be named, counted, linked or
    hinted at outside its own folder. That includes commit messages and screenshots.
  - Test browsers should start with no felt eggs found, so its box never shows.
- **Privacy:**
  - No real addresses or license plates. The car's plate THE CHEZ is fine.
  - Fictional addresses must be obviously fake, e.g. "P.O. Box 000".
  - Phone numbers are 555-01xx. Three stay on purpose: the two BBSes, 1-412-555-SAND and 1-412-555-SOFA, and Jenny's 867-5309, the song's number everyone tries.
  - No membership or lineage organizations.
  - No health, grief or money material. The exceptions are the lactose-intolerance game and the
    tin hearts' nod to the maintainer's pacemaker (on the cast page and in TURBO BUTTON).
- **Clowns are always friendly.** Never scary, villains or jump scares. The maintainer, Doc Leo,
  is in a clown club that entertains children.
- **Trademarks:** use generic words instead of casual trademarks ("building blocks", not a
  brand). Lyrics quoted word for word and historical tech names (Sound Blaster, MS-DOS,
  VGA…) stay; NOTICE.md lists them.
- **Spelling:** these notes are for you, not the player. Don't repeat them in game or site
  text ("two n's", "no clown nose", "never Dr."); just get them right.
  - **Gwinn** (two n's) is the troublemaker dog.
  - **Teddy** is the corgi; his ears match (neither is shorter).
  - **Doc Leo** is never "Dr. Leo".
  - **Clown Club** is the club's name, spelled normally (never "Klown Klub"); wherever it is
    lettered in a picture (signs, box art), the "o" in "Clown" is drawn as a red rubber nose.
  - **THE CHEZ** is a tomato-red 1976½ CitiCar with a black roof and only the door window
    from the side. It has two charcoal stripes with red between them and a white pinstripe,
    stepping up in an S behind the door; white wheels; square bumpers; and the charge port
    at the rear passenger side. Draw it with `games/kit/chez.ts`. Teddy rides in the front passenger seat, looking out
    the door window (never out the back: it has no back window). Keep "THE CHEZ" together on one line
    (a non-breaking space on the site; never wrapped between the words in a game).
- **Bard of Bizarre credits:** music and vocals made with Riffusion (now Google Flow
  Music); lyrics shaped by ChatGPT from the maintainer's prompts. Exceptions are noted in
  NOTICE.md. Riffusion, Producer.ai and Google Flow Music are one service under successive
  names (Riffusion renamed itself Producer.ai; Google bought it); never present them as
  different companies.
- **Originality:**
  - Write manuals and text fresh. Don't copy RSD's printed manual.
  - The maintainer's reference photos are reference only, unless they're asked for.
- **Voice clips:** a level's ending voice must play to the end (the next scene's intro cuts
  it). Bots wait for clips (`sim.waitForClip()`). Score and pickup sounds must not cut voices.

## Credits

Credit honestly, and as soon as you use anything that isn't this project's own. That covers:

- **Third-party code or data:** a library, an algorithm or approach you adapted, a header,
  a font, a file format spec, or a sample. Give its license and author in NOTICE.md, plus a
  short note in the file that uses it. The downloads carry their notices
  (`web/src/export/notices.ts`).
- **AI tools and models** used to make anything: music, voices, art, logos, words or code.
  Name the tool (e.g. Riffusion/Google Flow Music, ChatGPT, DeepAI, Claude)
  and what it made. If you use a new tool or model, add it to NOTICE.md and to the game's
  credits.
- **Source material:** the maintainer's own photos and recordings, public-domain works,
  and the original RSD files.

Check NOTICE.md before adding something, keep it in step with what actually ships, and say
in your report what credits you added.

## Before you finish

Run format, lint, tsc and vitest. Run the game checks above for any game you touched. Then report what
changed, the commits, how you verified it, and anything left undone.
